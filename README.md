# 苏州外国语学校运动会系统 (SFLS Sports Meeting System)

面向校运动会全流程的管理系统：学年数据隔离、双角色权限（管理员 / 班级领队）、项目与报名管理、AI 竞赛日程编排、分组、记录、秩序册生成、成绩与分数统计。

### 设计原则

- **学年为数据根**：绝大多数业务数据归属某一学年，切换学年即切换全站数据上下文。
- **分层清晰**：后端 models / schemas / services / routes 分离；前端 api / stores / views 分离。新增功能模块时按既有结构扩展即可。
- **同源部署**：对外只暴露一个端口，前端 Nginx 将 `/api` 反代到后端，无跨域问题，贴近正式产品形态。
- **配置即环境变量**：数据库、管理员、JWT、DeepSeek 等全部通过 `.env` 注入。
- **确定性+AI结合**：日程生成采用规则引擎打底，AI优化提升，确保可控可预测。

## 核心功能

### 0. 账号与权限 ✅

系统支持两类登录主体，同一登录页按填写内容区分：

- **管理员**：用户名 + 密码登录（年级/班级留空）。可访问全部模块。
- **班级领队**：登录页填写年级、班级（下拉可选、也可手输）+ 领队姓名（用户名位）+ 密码。按**当前激活学年**匹配班级 + 领队姓名 + 密码。
  - 数据隔离：领队只能看到并编辑**本班**报名数据（班级列表仅返回本班一行、详情/学生接口按班级校验）。
  - 只读放行：领队可读取当前学年、项目列表（报名勾选需要），但项目/学年的增删改、号码生成、秩序册、分数统计等仅管理员可用。
  - 领队密码由管理员在报名列表中以**明文**维护（便于查看/告知），默认 `admin_sfls`，可配置。

> JWT 主体：管理员为 `username`，领队为 `leader:{class_id}`；后端 `Principal` 统一封装，`require_admin` / `get_current_principal` 分别用于管理员专属与任意主体接口。

### 1. 学年设置 ✅

- 学年增删改查；名称唯一（格式如 `2026~2027`）。
- 可为每个学年设置运动会起止日期。
- 「设为当前」切换激活学年（同一时刻仅一个激活），顶栏实时展示当前学年。
- 删除学年有二次危险确认；删除激活学年后自动激活最近的一个。

### 2. 项目管理 ✅

- 维护本学年的比赛项目：项目名称、组别(年级)、性别(男/女/混合)、决赛队伍、团队/个人、场地、项目介绍。
- **唯一键**：同一学年内「项目名称 + 组别 + 性别」唯一，重复创建返回明确错误。
- 列表支持按名称搜索、按组别筛选；组别下拉可自定义输入（filterable + allow-create）。
- 表格支持列头排序，默认按「组别 + 性别 + 类型 + 项目名称」排序。
- 所有项目按当前激活学年自动隔离（后端 `get_active_year` 依赖），切换学年即切换项目集。
- 操作列：编辑、删除、查看报名详情。

### 3. 报名管理 ✅

- **班级管理**：
  - 以班级为单位报名：年级、班级、领队姓名、男生人数、女生人数（男/女各 ≤ 10）。
  - 唯一键「年级 + 班级」。
  - 列表操作列：查看详情、编辑、删除。

- **报名详情**（抽屉）：
  - **个人项目报名**：添加/编辑/删除学生（姓名、性别、可多选个人项目），号码列展示外部生成的号码。
  - **团队项目报名**：多选参加的团队项目并保存。
  - **项目过滤**：个人/团队项目按班级年级过滤；个人项目再按运动员性别过滤（男生看男子+混合，女生看女子+混合），切换性别时自动清除不匹配的已选项目。
  - **保存校验**（前后端双重、配置驱动）：每项限报人数、每人限报个人项目数（接力豁免）；运动员名单中的男/女人数须分别等于填写的男/女生人数。
  - 后端校验项目类型（团队项目不可作个人报名，反之亦然）。

- **生成号码**：
  - 一键为所有班级重新生成号码。
  - 号码从 301 起，班级按「年级(规范顺序) + 班级(数字优先)」排序。
  - 每班连续 10（男）+10（女）个号码槽位，有人占位、无人留白。

> **待补充**：Excel 上传功能（按需求分阶段，等待用户提供模板格式）。

### 4. 竞赛日程 ✅ (核心功能)

日程模块集成了**确定性规则生成**、**AI智能优化**、**手动编辑**、**成绩录入**、**决赛名单生成**等完整流程。

#### 4.1 配置面板

- **天数设置**：2天 / 3天赛程
- **跑道数**：径赛分道数（2-12道）
- **规则文本**：强规则（Hard Rules）、软规则（Soft Rules），可编辑

#### 4.2 确定性规则生成

点击「重新生成」，系统按以下逻辑产出合法日程：

1. **赛段自动分配**：
   - 2天：小学排第1天，初高中排第2天
   - 3天：小学排1.5天，初高中排1.5天

2. **预赛决赛判断**：
   - 报名人数 ≤ 决赛队伍数：直接决赛
   - 报名人数 > 决赛队伍数：先预赛后决赛

3. **分组规则**：
   - 一般按满跑道数分组
   - 末组不足一半跑道时，与上一组合并后均分为两组

4. **项目排序**：
   - 高负荷项目优先（短跑、跳跃等）
   - 同项目男女连续完成

5. **时间与场地**：
   - 项目组间隔时间控制（60米2分钟、100米3分钟、跳远30分钟等）
   - 同场地同时刻仅一项赛事
   - 不同场地可以并行进行不同项目

6. **冲突检测与解决**：
   - 自动检查运动员时间冲突
   - 解决策略优先级：调整分组 → 调整顺序 → 移动时段

#### 4.3 AI 优化 (DeepSeek 集成)

点击「AI 优化」，可输入自然语言需求（如"把跳远移到下午"），系统调用 DeepSeek API：

- 基于用户需求调整赛程顺序
- 仅调整时间顺序，不改变分组
- AI 历史记录保存，支持多轮优化
- 提供 AI 检查功能，验证是否违反规则

> **配置**：需在系统设置或 `.env` 中配置 `DEEPSEEK_API_KEY`。推荐使用 `deepseek-v4-pro` 模型。

#### 4.4 日程展示

- 按半天分段展示（大标题显示日期）
- 列：序号 / 项目名称 / 组别 / 性别 / 类型 / 赛次 / 组数(几组/取几名) / 时间 / 场地 / 详情
- 支持按日期、时段筛选
- 支持手动新增/编辑/删除赛次
- 操作列：查看详情、编辑、删除

#### 4.5 赛次详情（抽屉）

- 显示赛次元信息（项目、赛次、时间、场地）
- **分组分道表格**：分道 / 号码 / 姓名 / 年级班级 / 成绩 / 名次
- **成绩录入**：内联编辑（el-input / el-input-number），「保存成绩」按钮
- **自动排名**：保存成绩后自动计算名次
- **最高记录更新**：成绩录入时自动检测并更新历史记录
- **决赛名单生成**：预赛录入成绩后，点击「生成决赛名单」自动创建决赛赛次并按成绩取前N名

#### 4.6 手动编辑

- **编辑赛次**：修改时间、场地
- **新增赛次**：选择项目、日期、时段、赛次类型、时间、场地
- **删除赛次**：带二次确认
- **编辑分组分道**：支持调整选手分组（后续可扩展）

### 5. 最高记录 ✅

- 按项目维护历史最高记录（成绩、保持者、班级、日期）
- 成绩录入时自动检测并更新记录
- 支持手动编辑记录
- 列表支持按项目名称搜索、按组别筛选

### 6. 秩序册生成 ✅

- 一键导出 Word 格式秩序册
- 包含日程表、项目名单、报名统计等
- 格式规范，可直接打印使用

### 7. 分数统计 ✅

- 按班级统计得分（基于成绩名次自动计算）
- 支持按年级筛选
- 自动计算排名
- 表格展示：班级、年级、总分、排名

### 8. 系统设置 ✅

- DeepSeek API 配置管理（Key、Base URL、Model）
- 支持覆盖环境变量配置
- 密码修改需验证原密码

## 日程生成逻辑

### 强规则 (Hard Rules)

根据 `backend/app/services/schedule_rules.py`，系统遵循以下强规则：

1. **赛段分配**：
   - 两天赛程：小学（二~六年级）排第一天，初中、高中合排第二天
   - 三天赛程：小学排一天半，初中、高中合排一天半

2. **同项目男女连续完成**：同一项目名称下，男生和女生赛次连续排列

3. **赛制**：
   - 先预赛后决赛
   - 报名人数 ≤ 决赛队伍数时直接决赛，否则按人数分组预赛

4. **预赛连续**：同一项目的预赛小组须连续完成，中间不插入其它项目

5. **项目间隔时间**（关键规则）：
   ```
   60米: 2分钟      100米: 3分钟     800米: 5分钟
   1000米: 5分钟    100*2米: 6分钟   100*4米: 4分钟
   播种与收割: 15分钟              十人抓杆: 15分钟
   垒球: 30分钟     跳高: 30分钟     跳远: 30分钟
   袋鼠跳: 15分钟   师生同乐: 10分钟  侧向推实心球: 30分钟
   ```
   - 同一项目有预赛和决赛时，两者至少相隔半天
   - 尽可能满足间隔时间，如时间不够可以调整

6. **场地与并行**：
   - 同一场地同一时刻只能开展一项比赛
   - 不同场地可以同时进行不同项目

7. **冲突解决策略**（优先级顺序）：
   - 禁止同一运动员在同一时间重叠
   - 发生冲突时先尝试调整分组避免冲突
   - 如无法解决再调整项目顺序
   - 最后才移动到下一个时段

### 优化规则 (Soft Rules)

1. **高负荷项目优先**：短跑、跳跃等高负荷项目优先安排
2. **当日完成**：200 米以下径赛在赛次较少时尽量当日完成
3. **休息时间均衡**：自动检查兼项冲突，保证不同运动员、不同组别的休息时间合理且均衡

### AI 优化流程

1. 用户输入自然语言需求（如"把跳远移到下午"）
2. 系统将需求追加到 AI 历史记录
3. 调用 DeepSeek API，传入：
   - 当前日程
   - 强规则文本
   - 软规则文本
   - AI 历史记录（含用户新需求）
4. DeepSeek 返回优化建议（仅调整顺序，不改分组）
5. 前端展示优化结果，用户确认后应用

## 数据模型

### 核心表结构

#### 学年与配置
- **academic_years**: 学年基础信息（名称、起止日期、是否激活）
- **settings**: 系统配置（DeepSeek API等）
- **users**: 管理员账号

#### 项目与报名
- **events**: 比赛项目定义
  - 唯一键：`academic_year_id + name + group_name + gender`
  - 字段：名称、组别、性别、场地、决赛队伍数、是否团队、介绍
- **class_teams**: 班级报名单位（兼作领队账号）
  - 唯一键：`academic_year_id + grade + class_name`
  - 字段：年级、班级、领队姓名、男女生人数、登录密码（明文，仅管理员可见）
- **athletes**: 学生个人报名者
  - 关联：class_team_id
  - 字段：姓名、性别、号码
- **athlete_events**: 学生 ↔ 个人项目关联
- **class_team_events**: 班级 ↔ 团队项目关联

#### 竞赛日程
- **schedule_configs**: 日程配置
  - 每个学年一条
  - 字段：天数、跑道数、强规则、软规则、AI历史、生成时间
- **schedule_entries**: 赛次（某项目的预赛或决赛）
  - 字段：项目ID、第几天、上午/下午、预赛/决赛、序号、组数、取几名、时间、场地
- **schedule_groups**: 赛次下的小组
- **schedule_lanes**: 小组内的分道/席位
  - 关联：athlete_id（个人）或 class_team_id（团队）
  - 字段：分道号、成绩、名次

#### 记录与统计
- **records**: 历史最高记录
  - 字段：项目ID、成绩、保持者、班级、日期
- **scores**: 班级得分统计（自动计算）

### 数据隔离与级联

- **学年隔离**：所有业务表通过 `academic_year_id` 关联，切换学年即切换数据上下文
- **级联删除**：使用 `ondelete="CASCADE"`，删除学年/项目/班级时自动清理关联数据
- **唯一约束**：防止重复数据（项目、班级、报名关联等）

2. **前端**：
   - `api/`: 添加接口封装

## 常见问题

### Q: 如何配置 DeepSeek API？

A: 两种方式：
1. 环境变量：在 `.env` 中设置 `DEEPSEEK_API_KEY`
2. 系统设置：在前端「系统设置」页面配置（会覆盖环境变量）

推荐使用 `deepseek-v4-pro` 模型（不要用 `deepseek-chat`，会被限制到 8192 tokens）。

### Q: 端口 8687 可以改成 8686 吗？

A: 可以。修改 `.env` 中的 `APP_PORT=8686`，然后重启容器：
```bash
docker compose down
docker compose up -d
```

### Q: 如何重置测试数据？

A: 进入后端容器执行测试数据生成脚本：
```bash
docker compose exec backend python scripts/generate_test_data.py
```

### Q: 日程生成后可以手动修改吗？

A: 可以。支持：
- 编辑赛次时间、场地
- 手动新增/删除赛次
- 编辑成绩
- 手动编辑分组分道（后续可扩展更多编辑功能）

### Q: AI 优化会改变分组吗？

A: 不会。AI 优化仅调整赛次的时间顺序，不改变分组分道。如需调整分组，请使用「重新生成」或手动编辑。
